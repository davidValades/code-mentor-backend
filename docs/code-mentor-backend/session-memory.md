# Session closure, memory, and continuity — 2.8

The skill prepares the notes; the learner does not need to write the log manually. Writing and retrieving those notes requires accessible persistent storage and authorization. A skill or private plugin does not create folders or permissions or guarantee voice-mode tools.

## When it proposes updates

- After each meaningful block: evidence and a resume point, if authorized access is available.
- At the end of each session: a brief note of the work and outstanding items.
- At task closure, after three newly completed sessions since the last review, after difficulty in two separate sessions, or on request: one grouped update. Messages are not counted.
- Without new information: no changes. If the learner defers Work, the invitation is not repeated every turn.

A pause leaves the session open. Closing the app does not trigger an automatic save. This flow has no background processes, implicit synchronization, or scheduled reminders.

## What is retained

The goal, scope, concepts and prerequisites, exercises, changes and tests actually performed, responses, assistance level and interaction mode, errors and corrected terms, decisions with provenance, difficulties, questions, next action, and suggested review. It distinguishes reading, self-reported understanding, demonstrated understanding, guided practice, independent application, and later retrieval. Copying or saying “understood” does not demonstrate mastery.

It also retains how teaching was delivered: declared preferences, diagrams, analogies, traces, examples or combinations used, context, and results, including aids that did not work. When returning to a difficulty, it consults these records; it does not assign learners fixed learning styles or infer efficacy from one preference. Charts require real evidence and compatible utilities; a Markdown summary does not itself produce learning statistics.

## Chat without write access and Work

The tutor leaves one visible package with an ID and revision, included sessions, destination or “not configured,” note, and list of pending changes. It suggests that the user activate Work and attach or paste the package if the context is not available there. Preparing the package does not prove it was saved outside that conversation. Work is not required to continue learning.

Work must check its tools, the destination, the latest version, and already applied batches. It updates only what is authorized, preserves history, and reads the result. It does not create another copy to pretend it modified a read-only attachment. A retry preserves IDs and applies only pending changes; after a partial failure, it shows what was and was not saved.

The user decides when to activate Work; their plan's usage terms apply. There is no promised fixed cost or automatic credit purchase. While driving, the user is not asked to change modes, touch the screen, or attach documents.

## Locations and permissions

- General profile: concepts, difficulties, and achievements without company information.
- Work project: permitted context and references in the agreed local root; they are not automatically exported.
- Remote documents: only when a tool can write to their actual identities. Their IDs are not passed to the local CLI as paths.
- No destination: closure remains pending. Location setup and write/read verification happen once; support in one mode does not demonstrate support in another.

Operational notes are saved within existing authorization. Concept cards still require acceptance of their exact content. Sharing work context with another environment requires approval of the exact summary. The tutor's memory consists of these records, not a guarantee of general ChatGPT memory.

## Checking the version

The source declares version 2.8; the corresponding portable release version is 2.8.0. To check an installation, ask the agent to read its available `SKILL.md` and [session-close.md](../../skills/code-mentor-backend/references/session-close.md). Reading those pages on GitHub verifies the public source but does not prove they are installed in that chat. Then test a closure using fictional content and verify the original document through an independent read.

Building or publishing a package does not establish the version of an existing personal skill or private plugin. See [distribution and review status](submission-readiness.md) for the dated evidence and remaining checks.

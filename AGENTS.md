# Skill collection authoring

- Source instructions: compact, precise English. Use short imperatives, explicit conditions and one location per rule. Remove ceremony and duplication; retain negations, exceptions, uncertainty and execution order.
- Read only the target skill and relevant references. Use indexes/checkpoints to locate records; do not load whole knowledge libraries. Reuse verified context while its source/version remains current.
- Learner/user output follows each skill's own format and language rules. Compact source and coordination notes must not force telegraphic explanations, omit needed examples or change teaching behavior.
- Preserve code, schemas, CLI names, links, IDs and private storage paths. Keep safety, authorization and evidence contracts explicit. Do not compress historical records, user data or exact retry payloads by default.
- Coordination notes: goal; verified facts with sources; changes; checks/results; unresolved items; next action. Include only relevant state. Never present private reasoning or an unverified action as a result.
- For a new skill, start from templates/skill and bundle its needed resources. Root guidance does not automatically reach an independently installed skill; keep a small scoped context rule in its SKILL.md.
- Verify behavior and protected content after compression. Report measured words/bytes separately from tokenizer counts or runtime cost. No guaranteed percentage, speed or reasoning-token saving.
- Current implementation is an independent convention informed by Caveman. No upstream runtime, hooks, telemetry or global response mode is required. See docs/authoring.md.

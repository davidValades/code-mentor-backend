# Estudio guiado de documentación

Transforma una petición de estudio, un enlace o una documentación en una ruta pequeña adaptada al alumno. Reutiliza memoria, currículo y biblioteca; no crees un modo independiente ni otro perfil de progreso.

## Preparación

1. Recupera objetivo, evidencias, checkpoint y las fichas pertinentes del índice. Distingue lo observado de lo declarado; no conocer una evidencia no demuestra desconocimiento del alumno. Si falta una base que cambia el punto de partida, haz una comprobación breve y espera su respuesta.
2. Abre la documentación indicada y contrasta el contenido técnico con fuentes primarias, preferentemente Microsoft Learn para C#/.NET. No afirmes haber leído una URL sin acceso. Si falla, pide el fragmento mínimo y señala qué parte queda sin verificar; puedes trabajar con fundamentos conocidos identificando ese límite.
3. Comprueba la versión de C#/.NET aplicable cuando cambie la explicación o el código. La referencia oficial puede incluir funciones preliminares: separa lo compatible con el proyecto de lo nuevo o experimental. No presupongas la última versión en un proyecto existente.
4. Divide el tema por competencias observables y prerrequisitos. Presenta una ruta breve: objetivo, punto de partida y siguiente bloque; mantén el resto como plan, no como una explicación de todos los conceptos. Justifica el orden según la evidencia y las tareas actuales.

## Una unidad de aprendizaje

Consulta teaching.md. Enseña una sola idea principal: término técnico y explicación sencilla, ejemplo mínimo relacionado con lo que ya conoce, una predicción o pequeña práctica y espera. Usa esquemas si aclaran relaciones y ejemplos sintéticos si no hay autorización sobre código laboral. Da una pista antes de resolver el ejercicio y comprueba transferencia a un ejemplo distinto.

Una respuesta correcta con ayuda conserva esa ayuda en la evidencia. La explicación oral sirve para comprensión conceptual; reserva una práctica IDE si el objetivo requiere implementar o depurar. Un resultado erróneo puede exigir un prerrequisito; explica lo mínimo para continuar y prepara refuerzo posterior.

## Cierre y continuidad

Registra evidencias y checkpoint dentro del permiso operativo existente. Propón fichas y actualizaciones según knowledge-library.md, con aceptación del contenido antes de guardar. Vincula fuentes y secciones, fecha real de consulta, versión cuando importe, dificultades, siguiente práctica y repaso orientativo; no copies extensamente documentación externa. Conserva una ruta resumida en el perfil general o tarea del proyecto según el ámbito.

Ejemplo de enfoque, no currículo obligatorio: para «estudiar operadores», comprueba tipos/valores y bool cuando proceda, y prioriza comparaciones o condiciones si ayudan a la tarea actual. Después considera cortocircuito, nulabilidad, precedencia u otros grupos según evidencias. Reconocer `==` no prueba comprender referencias o sobrecargas; evita generalizar su comportamiento entre tipos. No conviertas la petición concreta de un jefe en regla general del equipo.

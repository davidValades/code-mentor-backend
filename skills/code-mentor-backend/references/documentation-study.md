# Guided documentation study

Turn a study request, link, or documentation into a small learner-adapted path. Reuse memory, curriculum, and library. Create no separate mode or progress profile.

## Preparation

1. Retrieve objective, evidence, checkpoint, and relevant indexed cards. Distinguish observed from reported; unknown evidence does not prove learner ignorance. If a missing foundation changes the starting point, check briefly and wait.
2. Open specified documentation; verify technical content against primary sources, preferably Microsoft Learn for C#/.NET. Never claim URL reading without access. If access fails, request the minimum excerpt; identify unverified content. Known fundamentals remain usable with that limitation stated.
3. Check applicable C#/.NET versions when they affect explanation/code. Official references may include preview features: separate project-compatible from new/experimental features. Never assume an existing project uses the latest version.
4. Divide by observable competencies and prerequisites. Present a brief path: objective, starting point, next block. Keep the rest as a plan, not explanations of every concept. Justify order through evidence and current tasks.

## One learning unit

Consult teaching.md. Teach one main idea: technical term, simple explanation, minimal example connected to prior knowledge, then prediction or small practice; wait. Diagram only when relationships become clearer. Without workplace-code authorization, use synthetic examples. Give a hint before solving; check transfer to a different example.

Record help alongside a correct assisted answer. Oral explanation supports conceptual understanding; reserve IDE practice when implementation/debugging is required. An incorrect result may reveal a prerequisite: explain only enough to continue; prepare later reinforcement.

## Closing and continuity

Record evidence/checkpoint within existing operational permission. Propose cards/updates per knowledge-library.md; obtain content acceptance before saving. Link sources/sections, actual access date, relevant version, difficulties, next practice, and suggested review. Avoid extensive copying of external documentation. Keep the summarized path in the general profile or project task according to scope.

Example approach, not mandatory curriculum: for “study operators,” check types/values and bool where appropriate; prioritize comparisons/conditions when useful to the current task. Then consider short-circuiting, nullability, precedence, or other groups according to evidence. Recognizing `==` does not prove understanding of references/overloads; avoid generalizing its behavior across types. Never turn a manager's specific request into a general team rule.
